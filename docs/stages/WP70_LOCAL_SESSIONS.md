# WP-70. Локальный вход и переподключение

Для сетевой основы используем Godot ENet и серверную SQLite. На GitHub проверили
официальный [Nakama SDK для Godot](https://github.com/heroiclabs/nakama-godot)
с лицензией Apache-2.0 и [пример интеграции](https://github.com/heroiclabs/nakama-godot-demo).
Возвращаемся к оценке Nakama при выборе реализации друзей и гильдий.

Когда задан `ATLANTIC_LOCAL_LOGIN_KEY`, сервер слушает только `127.0.0.1`. Ключ
должен содержать 32 случайных байта в hex. Сервер создаёт или находит аккаунт
`local-playtest` в SQLite. При входе проверяет ключ и версию протокола до допуска
соединения. Допускается одно активное соединение. Без переменной сохраняется
транспортный режим WP-02 для проверки совместимости версий.

Пакет входа, восстановления или выдачи сессии содержит версию протокола
(четыре байта little-endian), тип сообщения (один байт) и ключ или токен
(32 байта). Типы — вход 1, восстановление 2, выдача сессии 3. Сервер выдаёт
новый случайный токен после каждого успешного входа или восстановления.
Восстановление доступно в течение двух минут после обнаружения разрыва.
Токен хранится в памяти и теряется при перезапуске. Сервер связывает аккаунт
с идентификатором соединения, который назначает Godot.

`tools/smoke_enet.sh` проверяет обе конфигурации на отдельном процессе Godot.
Проверки сессий охватывают неверный ключ, несовместимую версию, вход,
восстановление и повторное использование старого токена.

До завершения WP-70 остаются многопользовательский вход, защищённый транспорт,
подключение штатного игрового клиента и авторизованные игровые RPC.
