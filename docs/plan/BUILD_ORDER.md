# Порядок создания игры (версия 2, после полного разбора вики)

> **Источник правды по статусу и порядку: `docs/plan/tasks.json` и сгенерированный из него `ROADMAP.md`** (команды `python3 tools/roadmap.py next|start|done|...`). Этот файл описывает задачи подробно; при расхождении верить tasks.json.

Работа разбита на **пакеты (WP)** по фазам и **вехам (M)**. Берите пакеты по порядку, соблюдая зависимости. Номера WP стабильны (на них ссылаются другие документы); новые пакеты добавлены с новыми номерами.
Перед любым пакетом прочитайте [DESIGN_GUARD.md](DESIGN_GUARD.md) (что нельзя ломать) и нужный файл из [wiki/](wiki/README.md) (факты оригинала).
Размеры: S (до дня), M (несколько дней), L (неделя и больше). Статус: ✅ выполнен, ◐ частично, пусто = не начат.

## Общие правила приёмки пакета
Все тесты зелёные; данные проходят `GameData.validate()`; числа в данных; для интерфейса просмотрены скриншоты (16:9 и 2.2:1); нет предупреждений Godot; обновлены документ раздела, `docs/DECISIONS.md`, `ROADMAP.md`; коммит в `main`.

## Шлюз перед каждой фазой (поиск на GitHub)
Перед первым пакетом каждой фазы исполнитель выполняет **шлюз** по [GITHUB_RESEARCH.md](GITHUB_RESEARCH.md): ищет подходящие библиотеки, шаблоны, ассеты и решения, записывает кандидатов
в `docs/stages/<фаза>_GITHUB_CANDIDATES.md` (название, лицензия, дата, что даёт, решение: внедрить, адаптировать, изучить, отклонить с причиной), берёт только MIT/Apache/CC0/CC-BY,
вносит выбранное в `third_party/` с атрибуцией и в `third_party/ASSETS.md`. Фаза не начинается без записи шлюза.
