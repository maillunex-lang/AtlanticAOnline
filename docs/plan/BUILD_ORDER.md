# Порядок создания игры

Работа разбита на **пакеты (WP)**, сгруппированные по фазам. Берите пакеты по порядку, соблюдая зависимости. Для каждого пакета: цель, зависимости, что сделать, файлы,
критерии приёмки. **Статус пакетов:** выполнен только WP-10 (см. колонку «Приёмка»); остальные не начаты. Актуальную очередь ведёт [../../ROADMAP.md](../../ROADMAP.md).

Общий критерий для всех: все тесты зелёные, данные проходят `GameData.validate()`, обновлены документы (`docs/`, `DECISIONS.md`, `ROADMAP.md`), коммит в `main`.
Размеры: S (до дня), M (несколько дней), L (неделя и больше).

## Рекомендуемая стратегия
1. Сначала **WP-10** (бой) и **WP-30** (квесты), они определяют остальное.
2. Затем **WP-20..WP-24** (данные регионов, карта мира, первый регион), чтобы получить играбельный вертикальный срез первых 20 уровней.
3. Параллельно **WP-00..WP-02**, затем **WP-70..WP-73**: сеть нужна к моменту, когда контента станет много (накопленный риск).
4. Регионы наращивайте по одному (WP-25, WP-26, WP-27), каждый с квестами и наёмниками.
5. Арт и звук подключайте, когда механики стабильны.

## Правила приёмки пакета
Каждый пакет закрывается, когда: работает в демо или в тесте, есть автопроверка, документ обновлён, скриншоты просмотрены (для интерфейса), числа вынесены в данные, нет предупреждений в логах Godot.
