## Зачем
Раньше боевая модель (GDD-04, вариант A «число ходящих растёт 1, 2, 3 ... до 5») строилась по вторичным источникам. Страницы вики-зеркала описывают правила точнее
и **отличаются** от неё. Нужно привести `BattleSim` к оригинальной логике очков действий (AP). Числа можно настраивать, структура правил должна совпасть.

## Правила оригинала (факты, пересказ)
| Правило | Суть |
|---------|------|
| Формация | Сетка 3x3, до 9 бойцов: герой и до 8 наёмников. У врагов такая же формация. Против игрока могут стоять до 3 групп монстров |
| Ходы | Стороны ходят по очереди, на ход 30 секунд. Первой ходит сторона, начавшая бой (в турнирах PvP случайно) |
| Очки действий | У каждого бойца свой запас AP. Чтобы совершить действие, нужно минимум 100. Максимум 299, минимум для штрафов около -50 (особые навыки). Каждый ход боец получает прирост AP (по умолчанию 50 при полной формации; если часть бойцов выключена, прирост у оставшихся больше). У каждого бойца свой прирост |
| Кто действует | В начале хода выбираются **до 5 бойцов с наибольшим AP** (и только те, у кого не меньше 100). Если у многих 100+, ходят пятеро с наибольшим запасом |
| Стоимости | Атака оружием 100. Магические навыки у каждого свой. Защита («Guard») 50: боец встаёт в оборону, его ход заканчивается. Смещение внутри формации 50. Обыск добычи 50 (на каждого). «Ждать» бесплатно, но ход не передаёт |
| Отрицательный AP | Если ход бойца активен, он может выполнить действие, даже когда стоимость превышает запас. После серии действий AP уходит вглубь минуса, поэтому следующие ходы пропускаются |
| Оглушение | Если по бойцу физическая атака попала 3 хода подряд, он оглушён. Магия комбо не добавляет. Комбо растёт максимум один раз за ход (две атаки в тот же ход считаются за одну). Если за ход не атаковали, счётчик сбрасывается. Оглушённый не действует и не получает AP |
| Гибель героя | В обычном бою гибель героя означает поражение. Героя в обычном бою нельзя воскресить. Наёмников воскрешают некоторые классы |
| Мана | Магические навыки тратят очки магии. Максимум растёт от интеллекта. Есть навыки, которые тратят и восполняют ману. У навыков есть перезарядка в ходах |
| Автобой | Нужна лицензия. Включается для всей формации или для отдельных наёмников. Навыки можно запретить для автобоя |
| Смерть и отступление | Потеря 10% носимого золота и небольшой доли опыта, у наёмников тоже. Отступление даёт те же потери. Защищает лицензия «благословение» |
| Режимы | Обычный бой (в том числе PvP) и TBS (тактический бой со свободным перемещением, **без AP**, для миссий и части квестов) |
| Опыт и уровни | Герой и каждый наёмник имеют свой уровень. При повышении даются +1 очко характеристик и +1 очко навыков, здоровье и мана восстанавливаются |
| Подстройка монстров | Часть монстров подстраивается под уровень сильнейшего героя в отряде, это влияет на урон и опыт |

## Что нужно изменить в нашей реализации
| Сейчас (GDD-04) | Нужно |
|-----------------|-------|
| `active_start`, `active_growth`: число действующих растёт | Убрать. В начале хода выбрать до `active_cap` (5) бойцов с наибольшим AP среди тех, у кого AP >= `ap_act_threshold` (100) |
| `ap_max` 100, `attack_cost` 40, `move_cost` 30 | `ap_max` 299, `ap_act_threshold` 100, `attack_cost` 100, `guard_cost` 50, `move_cost` 50. Нижней границы у обычных действий нет |
| `ap_regen` по классам: 35-55 | Прирост AP за ход: по умолчанию 50, зависит от бойца и растёт при выключенной части формации |
| Боец действует один раз, ход закрывается сам | Боец действует, пока его ход активен: можно несколько действий (если хватает логики стоимости), AP уходит в минус. Нужно определить правило «закрытия» хода бойца: **рекомендация** — одно основное действие на бойца за ход, после него боец неактивен, а смещение, защита и ожидание считаются по правилам оригинала |
| Нет защиты | Добавить действие `guard` (стоимость 50, ход бойца заканчивается, повышенная защита до следующего хода) |
| Нет оглушения | Счётчик комбо у бойца, оглушение на 3 подряд физических попадания, оглушённый пропускает ход и не получает AP |
| Нет маны | Поля `mp`, `max_mp`, стоимость навыка в мане, интеллект даёт макс. ману; восстановление |
| Победа: все враги убиты | Добавить: гибель героя стороны означает поражение стороны (для PvE и PvP) |
| Нет таймера в PvE | Таймер хода 30 секунд для игрока (в PvP уже есть) |
| Нет TBS | Отдельный режим (WP позже): свободное перемещение по сетке, без AP |
| Одна группа врагов | До 3 групп монстров в бою (формации врагов) |
| Автобой без ограничений | Лицензия на автобой, выбор навыков для автобоя |

## Порядок работ (пакет WP-10 из BUILD_ORDER.md)
1. Обновить `BattleRules` (новые параметры) и `BattleUnit` (AP, MP, комбо, оглушён, в обороне).
2. Переписать `_begin_turn` и выбор действующих, `submit` (стоимости, guard), конец хода и победу.
3. Обновить `BattleAI`, тесты `tests/battle/*`, добавить тесты на выбор пятёрки по AP, отрицательный AP, оглушение, гибель героя.
4. Данные: `data/skills.json` (стоимость в AP и мане, перезарядка), `data/progression.json` (прирост AP, максимум).
5. Клиент: на плитках бойцов показывать AP и маркер «активен» (зелёный круг у ног), меню действий получает «Защита»; таймер 30 секунд.
6. Обновить `docs/GDD04_COMBAT.md` и `docs/DECISIONS.md` (решение заменяет вариант A).
7. Баланс: прогнать боевые симуляции (автобой против групп), числа вынести в данные.
