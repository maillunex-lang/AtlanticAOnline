# GDD-04. Боевая система

Статус: **утверждено 2026-11-22**, ядро реализовано и покрыто тестами.
Модель хода: **A. Стороны ходят по очереди, число действующих бойцов растёт.**

## 1. Источники и их ограничения
Вики Atlantica недоступна (HTTP 402), механики собраны по вторичным источникам, которые расходятся в деталях.
Подтверждено несколькими источниками: сетка 3x3, отряд до 9 бойцов, в раунде действуют не все (до 5),
у наёмников есть очки действий, перемещение их тратит. Точные формулы и числа ниже **наши собственные**,
они вынесены в `BattleRules` и подлежат настройке игровыми тестами.

## 2. Поле боя
- У каждой стороны сетка 3x3, слот = ряд * 3 + колонка (0..8). Колонка 0 ближайшая к врагу.
- Отряд: до 9 бойцов (герой и до 8 наёмников). Смена формации вне боя бесплатна, в бою тратит AP.
- Дальность: ближний (MELEE) бьёт только по передней занятой колонке врага, дальний (RANGED) по любому бойцу.
  Когда передняя колонка вымерла, следующая становится доступной.

## 3. Ход
1. Ходит одна сторона. Число бойцов, которым разрешено действовать:
   `min(active_start + (N-1) * active_growth, active_cap, живых бойцов)`, где N номер хода этой стороны.
   По умолчанию 1, 2, 3, 4, 5, 5, ...
2. Каждый действующий боец выполняет **одно** действие: `attack`, `move` или `wait`.
   Игрок сам выбирает, кто из бойцов действует, поэтому формация и выбор ходящих это тактика.
3. В начале хода стороны каждый её боец получает AP (`ap_regen`, потолок `ap_max`).
4. Ход закрывается, когда сходили все действующие, либо досрочно (`end_turn`).
5. Раунд заканчивается после хода стороны B. Бой кончается победой, когда у стороны не осталось живых,
   или ничьей по истечении `max_rounds`.

## 4. Действия и очки действий (AP)
| Действие | Стоимость AP | Условия |
|----------|--------------|---------|
| attack | `attack_cost` (40) | цель жива, это враг, достижима по правилу дальности |
| move | `move_cost` (30) | слот 0..8, не текущий; если занят живым союзником, они меняются местами |
| wait | 0 | всегда доступно |

Боец без достаточного AP может только ждать. AP делает мощные формации ограниченными: нельзя бесконечно
менять позиции и бить каждый ход.

## 5. Урон
`урон = атака * K / (K + защита)`, затем множитель разброса (±`variance_pct`), затем критический удар
(`crit_chance_pct`, множитель `crit_mult_pct`), минимум 1. K = `def_scale` (100).
Случайность идёт только из `RandomNumberGenerator` с заданным зерном: бой воспроизводим по зерну и списку действий.

## 6. Архитектура
| Файл | Роль |
|------|------|
| `src/shared/battle/battle_rules.gd` | Параметры баланса, одно место настройки |
| `src/shared/battle/battle_unit.gd` | Данные бойца |
| `src/shared/battle/battle_sim.gd` | Симуляция: `submit(action)`, `end_turn()`, `to_dict()`, журнал событий |
| `tests/battle/test_battle_sim.gd` | 22 теста правил |

Принципы: симуляция не знает про сцены, сеть и UI. Сервер вызывает её как источник истины, клиент
проигрывает полученные события анимациями и использует ту же симуляцию для предпросмотра.
Ответ `submit` содержит `ok`, код ошибки (`wrong_side`, `already_acted`, `active_limit`, `no_ap`,
`bad_target`, `unreachable`, `bad_slot`, `bad_action`, `unknown_unit`, `battle_over`) и список событий.
События (`turn_started`, `attack`, `move`, `wait`, `turn_ended`, `battle_ended`) это формат обмена с клиентом.
Снимок `to_dict()` нужен для переподключения во время боя.

## 7. Заимствования
Структуру «боец, действие, события боя» мы взяли как идею из godot-open-rpg (MIT, GDQuest), код оттуда не копировался:
у нас сетка 3x3, серверная авторитетность и растущее число ходящих. Остальные кандидаты изучены, не внедрены (см. docs/stages/GDD04_GITHUB_CANDIDATES.md).
