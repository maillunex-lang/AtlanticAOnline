# GDD-04. Боевая система

Версия 3 (WP-10 и WP-11A, 2026-11-22). Статус: **реализовано и покрыто тестами** (`tests/battle`, `tests/world/test_encounters.gd`, `tests/social`).
Версия 1 (вариант A «число ходящих растёт 1, 2, 3 ... до 5») **заменена** моделью очков действий оригинала, см. [plan/COMBAT_REVISION.md](plan/COMBAT_REVISION.md).

## 1. Источники и ограничения
Правила очков действий взяты из зеркала вики Atlantica (rikagro.ru, см. [SOURCES.md](SOURCES.md)): сетка 3x3, порог 100, до 5 действующих,
стоимости, оглушение, гибель героя. **Структура правил совпадает с оригиналом, числа урона и формулы наши** и вынесены в `BattleRules` и данные для настройки.
Неподтверждено: точная формула роста прироста AP при выключенной части формации (в коде параметр `ap_gain_per_missing`, по умолчанию 0).

## 2. Поле боя
- У каждой стороны сетка 3x3, слот = ряд * 3 + колонка (0..8). Колонка 0 ближайшая к врагу.
- Отряд: до 9 бойцов (герой и до 8 наёмников). Смена формации вне боя бесплатна, в бою тратит AP (`move`).
- Дальность обычной атаки и зона поражения определяются [шаблоном оружия](plan/COMBAT_PATTERNS.md). Симуляция, ИИ и подсветка используют `BattleSim.hit_set()`. Когда передняя колонка вымерла, следующая становится доступной.

## 3. Ход
1. Стороны ходят по очереди. Первой ходит сторона A (конструктор принимает `first_side`; в PvP-лигах сторону выбирает вызывающий код).
2. **Начало хода стороны**, для каждого живого бойца этой стороны: снимается защита (`guarding`), восстанавливается мана
   (`mp_regen_pct` от максимума), уменьшаются перезарядки навыков. Оглушённый боец пропускает этот ход: оглушение снимается, AP он **не** получает.
   Остальные получают прирост AP: `ap_regen` бойца (по умолчанию 50) плюс `ap_gain_per_missing` за каждого отсутствующего бойца формации; запас не выше `ap_max` (299).
3. **Выбор действующих:** бойцы с `ap >= ap_act_threshold` (100) сортируются по AP по убыванию (при равенстве меньший слот, затем меньший id);
   действуют первые `active_cap` (5). Список виден в `sim.active_ids` и в событии `turn_started`.
4. Каждый действующий боец делает **одно основное действие** (`attack`, `skill`, `guard`, `wait`) и может один раз за ход сместиться (`move`),
   смещение не расходует основное действие. Порядок бойцов выбирает игрок.
5. Ход закрывается сам, когда сходили все действующие, либо досрочно `end_turn()`. Если действовать некому, ход пропускается (`turn_skipped`);
   `max_idle_turns` (12) пропусков подряд означают ничью.
6. **Конец хода:** тикают модификаторы бойцов стороны. Комбо: каждый боец противника, получивший за этот ход физический удар, увеличивает счётчик
   (максимум +1 за ход при любом числе ударов); не получивший сбрасывает счётчик. На `stun_combo` (3) счётчик обнуляется и боец оглушается (`stunned`).
   Магический урон комбо не добавляет.
7. Раунд заканчивается после хода стороны B. После `max_rounds` (40) раундов ничья.

## 4. Действия и очки
| Действие | Стоимость AP | Условия |
|----------|--------------|---------|
| attack | `attack_cost` 100 за весь удар | цель жива, враг, достижима по шаблону оружия |
| skill | `cost_ap` навыка (в данных) и `cost_mp` маны | навык изучен, не на перезарядке, хватает маны, цель допустима |
| guard | `guard_cost` 50 | защита `+guard_def_pct` % (50) до начала следующего хода бойца |
| move | `move_cost` 50 | один раз за ход, слот 0..8, не текущий; занятый живым союзником слот меняется местами |
| wait | 0 | всегда |

Требование одно: **боец активен (AP не ниже порога 100)**. Действие списывает свою стоимость, **AP может уйти в минус** (пример: навык за 120 при 100 AP даёт -20);
такой боец несколько ходов не сможет действовать, пока прирост не вернёт AP к порогу. `can_afford()` возвращает `no_ap`, `no_mp`, `on_cooldown`, `unknown_skill`.

## 5. Победа и поражение
Сторона проигрывает, когда **погиб её герой** (боец с `is_hero`, то есть наёмник `tier == "hero"`), даже если наёмники живы.
Если у стороны героя нет (враги в PvE), она проигрывает, когда погибли все. Одновременное поражение обеих сторон и исчерпание раундов дают ничью (`Winner.DRAW`).
Проверка: `sim.side_lost(side)`.

## 6. Урон
`урон = атака * сила_навыка% * K / (K + защита)`, где защита умножается на `(100 + guard_def_pct) / 100` у бойца в обороне, K = `def_scale` (100);
затем разброс ±`variance_pct`, критический удар (`crit_chance_pct`, `crit_mult_pct`), минимум 1. Случайность только из `RandomNumberGenerator` с заданным зерном:
бой воспроизводим по зерну и списку действий. Сила навыка растёт на `skill_power_per_level_pct` за уровень навыка. Лечение: `атака * сила%`.

## 7. Мана и навыки
- `mp`, `max_mp` у бойца; максимум `data/progression.json` → `mp` (`base 40`, `per_level 3`), для наёмника считается в `Mercenary.compute_stats`.
- Навык: `cost_ap` (в AP), `cost_mp`, `cooldown` (в ходах своей стороны), `magic` (магический не даёт комбо). Магическими сейчас объявлены навыки посоха.
- Бафы и дебафы, модификаторы с длительностью (`StatBlock`), сгорают по ходам стороны владельца.

## 8. Архитектура
| Файл | Роль |
|------|------|
| `src/shared/battle/battle_rules.gd` | Параметры баланса, одно место настройки |
| `src/shared/battle/battle_unit.gd` | Данные бойца (AP, MP, герой, защита, оглушение, комбо) |
| `src/shared/battle/battle_sim.gd` | Симуляция: `submit(action)`, `end_turn()`, `can_act`, `can_afford`, `legal_targets`, `to_dict()`, журнал событий |
| `src/shared/battle/battle_ai.gd` | Выбор действия для врагов и автобоя (детерминирован) |
| `src/shared/battle/skill_def.gd` | Определение навыка из `data/skills.json` |
| `tests/battle/` | Тесты правил, навыков, ИИ |

Симуляция не знает про сцены, сеть и UI. Действия: `{"type": "attack|skill|guard|move|wait", "actor": id, ...}`.
Коды ошибок: `battle_over`, `unknown_unit`, `wrong_side`, `dead`, `not_active`, `already_acted`, `no_ap`, `no_mp`, `on_cooldown`, `unknown_skill`,
`bad_target`, `unreachable`, `bad_slot`, `already_moved`, `bad_action`.
События: `turn_started` (поле `active`: id действующих), `attack`, `skill`, `damage`, `heal`, `modify`, `guard`, `move`, `wait`, `stunned`, `stun_ended`,
`turn_skipped`, `modifiers_expired`, `turn_ended`, `battle_ended`. Снимок `to_dict()` нужен для переподключения во время боя.

## 9. Клиент (демо)
Внизу плитки бойцов (в оригинале активные подсвечены): тап по готовому бойцу открывает меню действий (атака, навыки, смещение, защита, ждать) с ценой в ОД и МП.
Недоступные бойцы затемнены, у оглушённого метка «ОГЛУШ». Подробности вёрстки: [EDITING.md](EDITING.md).
