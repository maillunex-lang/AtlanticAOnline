# GDD-02. Техническая архитектура

Статус: **утверждено 2026-11-22**. Решения: Godot headless-сервер с общим кодом (DECISIONS.md).

## 1. Общая схема

```
Android-клиент (Godot 4.7, Mobile renderer)  <--ENet/UDP-->  Сервер (Godot headless, Linux)
        отображение, ввод, анимации                          правила, бой, лут, экономика
                      \                                      /
                       общий код: src/shared (правила, формулы, константы, протокол)
                                                             |
                                                      SQLite (прототип) -> PostgreSQL
```

Принцип: клиент отправляет **намерения** («атаковать клетку X»), сервер проверяет и считает результат,
клиент воспроизводит его. Клиенту не доверяем ни урон, ни лут, ни валюту.

## 2. Структура репозитория

| Путь | Назначение |
|------|-----------|
| `src/shared/` | Код, общий для клиента и сервера: правила боя, формулы, протокол. Без обращений к UI и БД |
| `src/server/` | Серверная логика: сессии, комнаты боя, сохранение |
| `src/client/` | UI, сцены, ввод, анимации |
| `src/boot.gd`, `scenes/boot.tscn` | Точка входа: режим сервера, если есть фича `dedicated_server` или аргумент `--server` |
| `tests/` | Тесты gdUnit4 (запускаются в CI) |
| `addons/gdUnit4/` | Тестовый фреймворк (MIT) |
| `third_party/` | Лицензии и реестр сторонних компонентов |

## 3. Сеть

- Транспорт: ENet (UDP) через встроенный MultiplayerAPI Godot. Порт по умолчанию 7777, до 256 клиентов на процесс.
- Версия протокола `NetConfig.PROTOCOL_VERSION`: стороны обмениваются 4-байтовой версией через SceneMultiplayer на этапе подключения. При несовпадении сервер отклоняет клиента до игровых RPC.
- Формат сообщений: RPC Godot. Protobuf (godobuf) не используем, вернёмся при проблемах с трафиком.
- Бой пошаговый, поэтому трафик небольшой: по сети идут команды хода и результаты хода, без потока позиций.
- Переподключение: состояние боя хранит сервер, клиент после обрыва запрашивает текущее состояние комнаты.
- Масштабирование: один процесс сервера = один мир (шард). Бой позже выносится в отдельные процессы-комнаты (решение 2).

Пилот учёта зон запускается на loopback при двух разных локальных ключах `ATLANTIC_LOCAL_LOGIN_KEY` и `ATLANTIC_LOCAL_LOGIN_KEY_SECOND`. Протокол v2 позволяет двум тестовым персонажам войти в мир и запросить переход между Оазисом Миража и Поющими дюнами. Сервер проверяет переход, сохраняет зону и отправляет число активных персонажей в текущей зоне. Отключение убирает персонажа из счётчика. Сценарий проверяет `tools/smoke_enet.sh`. Полноценное перемещение игрового клиента остаётся частью WP-70.


## 4. Хранение данных

- Прототип: SQLite через godot-sqlite (MIT). Бинарники GDExtension берём из релизов (в git их нет) и подключаем под Linux-сервер.
- Доступ к БД только через слой `src/server/db/` с интерфейсом репозиториев, чтобы заменить SQLite на PostgreSQL без правок игровой логики.
- Клиент БД не использует. Локально хранятся только настройки.
- `ServerDatabase` управляет соединением, внешними ключами и миграциями через `PRAGMA user_version`. `PlayerRepository` создаёт записи аккаунта и персонажа и сохраняет игровой прогресс, сумку, журнал квестов и отряд единым транзакционным снимком.
- Снимок хранится как Godot Variant без объектов и сохраняет целочисленные ключи формации. Чтение и запись ограничены владельцем персонажа. Номер ревизии защищает от перезаписи устаревшим снимком. Подключение к сетевому входу и сессиям относится к пакетам сетевой части.

## 5. Авторизация и безопасность

- Аккаунт: логин и пароль (хэш с солью на сервере), позже вход через Google Play Games.
- Сессия: серверный токен, срок жизни и обновление.
- Сервер проверяет каждую команду: права, дистанцию, очередь хода, достаточность ресурсов.
- Лимиты частоты запросов на соединение, отключение при нарушении.
- Передача по сети пока без шифрования; шифрование (DTLS) включаем перед открытым тестом.

## 6. Сборка и CI

- GitHub Actions по образцу godot-ci, образ `barichello/godot-ci:4.7.2` (образ с такой версией существует).
- Задачи: тесты gdUnit4 → сборка Linux-сервера → debug-APK. Файл `.github/workflows/ci.yml`.
- Export-пресеты: `export_presets.cfg`: Android arm64-v8a, Linux Server с флагом `dedicated_server`.
- Релизный keystore не хранится в репозитории: передаётся секретами GitHub (docs/BUILD.md).
- Горизонтальная ориентация зашита в `project.godot` (`window/handheld/orientation=4`, sensor landscape).

## 7. Риски

| Риск | Мера |
|------|------|
| Godot headless хуже масштабируется, чем специализированный сервер | Выносим бой в процессы-комнаты, шардируем миры; граница определена общим кодом `src/shared` |
| GDExtension SQLite требует glibc ≥ 2.35 на сервере | Хостить на Ubuntu 22.04+ или пересобрать |
| Вшитые в клиент правила легко читаются | Сервер авторитетен, клиентская копия нужна только для предпросмотра |
| Ограничения Google Play (target API, формат AAB) | Перейти на AAB и актуальный target SDK перед выпуском (GDD-12) |
